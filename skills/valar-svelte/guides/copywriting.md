# 界面文案

> 本规范由 Valar 维护者定稿，用于约束界面文案的克制程度、语气与格式；后续调整须经维护者确认，AI 不得擅自改写。

## 克制原则：用中性标题本身说话

- **默认不写说明文字**：尽量减少解释性副标题、段落和底部提示卡，靠准确、中性的标题与输入框占位符自解释。
- **仅在必要时补一行**：只有当用户不看说明就会填错，或操作会触发不可逆后果（如格式限制、计费、删除影响）时，才补充一行简短说明。

## 语气与用词

- **冷静、中性、直给（工具感）**：客观陈述事实与结果；不卖萌、不抒情、不用感叹号和营销夸大词（用“已保存”，不用“太棒了！保存成功！”）。
- **状态词全站统一**：使用简短、中性的固定状态词（如“进行中 / 已完成 / 已暂停”），不混用口语或随意中英夹杂。

## 按钮文案

- **明确动作动词（2–4 字）**：常规操作使用明确动词（如“保存 / 创建 / 添加 / 应用”）。
- **危险确认写明对象**：删除或不可逆操作的确认按钮必须写出动作与对象（如“删除项目”“移除成员”），禁止使用笼统的“确定 / 好的”。
- **取消统一命名**：取消类操作统一使用“取消”。

## 空状态、报错与高危确认（一句话封顶）

- **空状态**：中性标题 + 1 个操作按钮（如“暂无项目” + “新建项目”），不写鸡汤或冗长引导段。
- **错误提示**：直接写「错在哪 + 怎么改」。
- **高危确认**：只写「具体动作 + 不可恢复影响」。

## 占位符、图标与排版细节

- **占位符只给格式示例**：如 `name@company.com`，不写“请输入邮箱”这类重复标签的废话。
- **不滥用 Emoji**：禁止用 Emoji 充当标题装饰或替代功能图标，图标统一来自项目配置的图标库。
- **中英文与标点**：中英文与数字之间保留标准空格（如“共 12 项”“导出 CSV”），中文界面使用规范中文标点。
- **等宽数字对齐**：金额、计数、表格数值、百分比与时间戳一律启用 `tabular-nums`，保证纵向对齐且变化不抖动。
